= Appendix: MCP Gateway

include::partial$console-access.adoc[]

Instead of connecting OpenShift Lightspeed to each MCP server individually, you can route all MCP tool calls through a single, centrally managed gateway endpoint. The gateway aggregates every registered MCP server behind one URL, so platform teams can apply consistent authentication, authorization, and policy enforcement to every tool call. From the perspective of OpenShift Lightspeed, the gateway is just a single MCP server.

This appendix deploys the full stack behind the gateway: Red Hat OpenShift AI, Connectivity Link with its MCP Gateway, the MCP Lifecycle operator, and the MCP server for Red Hat OpenShift. Most of the work happens in the *Bastion* tab. Two more appendix modules build on this one: xref:module-13.adoc[authentication, authorization, rate limiting, and tracing] at the gateway, and xref:module-14.adoc[guardrails] on top.

[#install-rhoai]
== 1. Install Red Hat OpenShift AI

Red Hat OpenShift AI is not yet published in the `redhat-operators` catalog on OpenShift 5. Point the cluster at the RHDP snapshot of the 4.22 Red Hat Operators catalog instead.

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: operators.coreos.com/v1alpha1
kind: CatalogSource
metadata:
  name: redhat-operators-snapshot
  namespace: openshift-marketplace
spec:
  sourceType: grpc
  image: quay.io/rhpds/olm_snapshot_redhat_catalog:v4.22_2026_11_11
  displayName: Red Hat Operators (4.22 Snapshot)
  publisher: Red Hat AgnosticD
  priority: -500
  grpcPodConfig:
    extractContent:
      cacheDir: /tmp/cache
      catalogDir: /configs
    memoryTarget: "30Mi"
    securityContextConfig: restricted
EOF
----

Wait for the catalog to be ready:

[source,bash,role="execute"]
----
oc wait catalogsource/redhat-operators-snapshot -n openshift-marketplace \
  --for=jsonpath='{.status.connectionState.lastObservedState}'=READY --timeout=300s
----

[#deploy-mcp-server]
== 2. Deploy the MCP server for Red Hat OpenShift

Deploy the MCP server for Red Hat OpenShift as an `MCPServer` resource, with its configuration, service account, and RBAC. The service account is bound to the standard `edit` cluster role, which grants read and write access to cluster resources without allowing RBAC or namespace management: the write tools can create, update, and delete workloads.

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: mcp-servers
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: openshift-mcp-server
  namespace: mcp-servers
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: openshift-mcp-server-edit
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: edit
subjects:
  - kind: ServiceAccount
    name: openshift-mcp-server
    namespace: mcp-servers
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: openshift-mcp-server-config
  namespace: mcp-servers
data:
  config.toml: |
    log_level = 5
    port = "8080"
    toolsets = ["core", "config", "observability/metrics", "netedge", "ossm"]
    cluster_auth_mode = "kubeconfig"
    read_only = false
    disable_destructive = false
EOF
----

Now create the MCP server. In the OpenShift AI web console:

* Open *AI hub* > *MCP servers*
* Open the Catalog tab
* Open the *Red Hat OpenShift MCP server* entry
* Click *Deploy MCP server*.
* In the deployment dialog, enter `openshift-mcp-server`, then select project `mcp-servers`.
* In the generated YAML, confirm that the ConfigMap name is openshift-mcp-server-config and under runtime.security.serviceAccountName set `serviceAccountName: openshift-mcp-server`.

The YAML configuration should look like:

[source,yaml]
----
runtime:
  security:
    serviceAccountName: openshift-mcp-server
config:
  port: 8080
  path: /mcp
  arguments:
    - '--config'
    - /etc/mcp-config/config.toml
  storage:
    - path: /etc/mcp-config
      source:
        type: ConfigMap
        configMap:
          name: openshift-mcp-server-config
----

* Then click *Deploy*.
* Wait for the Status show _Avaiable_.

Wait for the MCP server to be ready:

[source,bash,role="execute"]
----
oc wait --for=condition=Ready mcpserver/openshift-mcp-server -n mcp-servers --timeout=600s
----

== 3. Install Connectivity Link

Connectivity Link provides the Gateway API infrastructure and the authentication components that the MCP Gateway builds on.

Start by creating the GatewayClass:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: gateway.networking.k8s.io/v1
kind: GatewayClass
metadata:
  name: openshift-default
spec:
  controllerName: openshift.io/gateway-controller/v1
EOF
----

Then, install the Connectivity Link operator

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: kuadrant-system
---
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: kuadrant
  namespace: kuadrant-system
spec:
  upgradeStrategy: Default
---
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: rhcl-operator
  namespace: kuadrant-system
spec:
  channel: stable-1.5
  installPlanApproval: Automatic
  name: rhcl-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
EOF
----

Wait for the operator installation to complete:

[source,bash,role="execute"]
----
until oc get csv -n kuadrant-system -l operators.coreos.com/rhcl-operator.kuadrant-system="" -o name 2>/dev/null | grep -q .; do

oc wait csv -n kuadrant-system -l operators.coreos.com/rhcl-operator.kuadrant-system="" --for=jsonpath='{.status.phase}'=Succeeded --timeout=600s

Then create the `Kuadrant` custom resource:

Wait for the Kuadrant instance to become ready:

----
oc wait kuadrant/kuadrant --for="condition=Ready=true" -n kuadrant-system --timeout=600s
----

[#deploy-mcp-gateway]
== 4. Deploy the MCP Gateway

With Connectivity Link 1.5, the `Kuadrant` custom resource deploys the MCP Gateway controller automatically: the `mcp-gateway-controller` pod runs in the `kuadrant-system` namespace, and the `mcp.kuadrant.io` custom resource definitions are already in place. Confirm that the controller is running:

[source,bash,role="execute"]
----
until oc get deployment/mcp-gateway-controller -n kuadrant-system >/dev/null 2>&1; do
  echo "Waiting for the MCP Gateway controller to be created..."
  sleep 10
done
oc wait --for=condition=Available deployment/mcp-gateway-controller -n kuadrant-system --timeout=300s
----

Then create the `Gateway` and the `MCPGatewayExtension` that activates the gateway on it. The Gateway has two listeners: the `mcp` listener has the gateway's own hostname and serves the broker endpoint that clients talk to, and the `mcps` listener is a wildcard listener where every registered MCP server attaches with its own hostname:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: mcp-system
---
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: mcp-gateway
  namespace: mcp-system
  annotations:
    networking.istio.io/service-type: ClusterIP
spec:
  gatewayClassName: openshift-default
  listeners:
    - name: mcp
      hostname: mcp-gateway-openshift-default.mcp-system.svc.cluster.local
      port: 8080
      protocol: HTTP
      allowedRoutes:
        namespaces:
          from: All
    - name: mcps
      hostname: "*.mcp.internal"
      port: 8080
      protocol: HTTP
      allowedRoutes:
        namespaces:
          from: All
---
apiVersion: mcp.kuadrant.io/v1
kind: MCPGatewayExtension
metadata:
  name: mcp-gateway-extension
  namespace: mcp-system
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: mcp-gateway
    namespace: mcp-system
    sectionName: mcp
  httpRouteManagement: Enabled
  privateHost: http://mcp-gateway-openshift-default.mcp-system.svc.cluster.local:8080
EOF
----

Wait for the extension to become ready:

[source,bash,role="execute"]
----
oc wait --for=condition=Ready mcpgatewayextension/mcp-gateway-extension -n mcp-system --timeout=300s
----

Enable the Connectivity Link console plugin to visualize and manage the gateway from the web console:

[source,bash,role="execute"]
----
oc patch console.operator.openshift.io cluster --type json \
  -p '[{"op":"add","path":"/spec/plugins/-","value":"kuadrant-console-plugin"}]'
----

The console reloads automatically. Log in again:

* *Username:* `{openshift_cluster_admin_username}`
* *Password:* `{openshift_cluster_admin_password}`

A *Connectivity Link* section appears in the navigation menu. Its *MCP management* pages list the gateway extensions, the registered MCP servers with their online status, and the attached policies, and the *MCP Inspector* lets you validate and run individual tools directly.


[#register-mcp-server]
== 5. Register the MCP server

Expose the MCP server to the gateway with an `HTTPRoute` labeled for discovery, then register it with an `MCPServerRegistration`. The route attaches to the wildcard `mcps` listener with a hostname of its own: the gateway routes the broker and every registered server by Host header, so each server needs a distinct hostname — otherwise tool calls forwarded to the server land on the broker's route instead:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: openshift-mcp-server
  namespace: mcp-servers
  labels:
    mcp-server: 'true'
spec:
  hostnames:
    - openshift-mcp-server.mcp.internal
  parentRefs:
    - group: gateway.networking.k8s.io
      name: mcp-gateway
      namespace: mcp-system
      sectionName: mcps
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /mcp
      backendRefs:
        - name: openshift-mcp-server
          port: 8080
---
apiVersion: mcp.kuadrant.io/v1
kind: MCPServerRegistration
metadata:
  name: openshift-mcp-server
  namespace: mcp-servers
spec:
  prefix: openshift_
  path: /mcp
  category:
    - openshift
  hint: >-
    Inspect and manage OpenShift cluster resources — pods, workloads, nodes,
    events, and configuration.
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: openshift-mcp-server
    namespace: mcp-servers
EOF
----

Wait for the registration to discover the server's tools:

[source,bash,role="execute"]
----
oc wait --for=condition=Ready mcpsr/openshift-mcp-server -n mcp-servers --timeout=300s
oc get mcpsr -n mcp-servers
----

[#configure-ols]
== 6. Point OpenShift Lightspeed at the gateway

Finally, reconfigure the `OLSConfig` to route MCP tool calls through the gateway. The gateway is reachable in-cluster at the listener hostname, exposes its Streamable HTTP endpoint at the `/mcp` path, and the `Authorization` header forwards the logged-in user's bearer token so the gateway can authorize each request. Setting `introspectionEnabled` to `false` also shuts down the operator-managed OpenShift MCP server that the cluster interaction module used, so its tools are not duplicated next to the ones federated through the gateway:

[source,bash,role="execute"]
----
oc patch olsconfig cluster --type merge -p '{"spec":{"featureGates":["MCPServer"],"ols":{"introspectionEnabled":false},"mcpServers":[{"name":"mcp-gateway","url":"http://mcp-gateway-openshift-default.mcp-system.svc.cluster.local:8080/mcp","timeout":30,"headers":[{"name":"Authorization","valueFrom":{"type":"kubernetes"}}]}]}}'
----

The operator picks up the change, rolls out the OpenShift Lightspeed app server pod with the new configuration, and reports the overall status on the `OLSConfig` again. Wait for both before using the assistant:

[source,bash,role="execute"]
----
oc rollout status deployment/lightspeed-app-server -n openshift-lightspeed --timeout=300s
oc wait olsconfig cluster --for=jsonpath='{.status.overallStatus}'=Ready --timeout=600s
----

Once the app server is running, the intelligent assistant discovers the tools of every MCP server registered behind the gateway, prefixed with the registration prefix. Ask a question that requires cluster introspection and the tool calls now route through the gateway:

[source,role="copypaste"]
----
Show me the pods running in the lightspeed-demo namespace.
----

The assistant calls the `openshift_pods_list` tool — the `openshift_` prefix marks it as a tool federated through the gateway rather than the operator-managed server.
